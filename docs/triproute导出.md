### 2. **CHI-40 图层代码与验收标准不一致（实现 bug）**

- Polyline 代码里写死 

  strokeStyle="dashed"

  ，但验收标准明确要求：

  - **总览模式** → 虚线
  - **单天模式** → 实线

- 当前代码无论选哪天都是虚线，**验收标准无法通过**。

- 另外，标记点编号 idx + 1 是**按天内重新计数**（总览时每一天都从 1 开始），用户会以为第 3 天第 1 个点是全局第 1 个，容易混淆。

### 3. **导出流程两步 Bottom Sheet 体验差**

- 先选范围 → 再点“继续选择软件” → 再选地图，**多一次点击**。
- 警告出现在 Step 1，但按钮只有“仍然导出 / 改为按天导出”，用户选“仍然导出”后还要再走 Step 2，流程割裂。
- 与 CHI-40 联动“当前激活图层自动预选”没有给出具体实现代码（如何把 activeLayer 传给 ExportScopeSheet？），容易漏实现。

### 4. **Apple Maps 导出兼容性隐患**

- 设备检测只靠 

  navigator.userAgent

   正则（

  /iPad|iPhone|iPod|Macintosh/

  ），在：

  - iPadOS 伪装成桌面 Safari 时
  - 某些国产浏览器
  - Windows 上用 Safari（极少见但存在） 会误判，导致 maps:// 直接跳转失败或错误 toast。

- 非 Apple 设备仍尝试打开 https://maps.apple.com/...，但 web 版对 +to: 多途经点支持**极差**（经常只显示起点和终点），用户会以为导出失败。

- 所以彻底放弃设备检测，用户选择就跳转

### 5. **Google Maps 导出细节缺失**

- waypoints 只传 lat,lng，**不带地点名称**（而高德 via 带 name）。用户在 Google Maps 里看到的途经点全是“未命名”，体验差。
- 没有做任何截断，依赖 UI 提示“免费版可能只显示部分路线”，但用户经常忽略提示，实际打开后 waypoints 被 Google 静默丢弃。

### 6. **单天行程与边缘情况处理不足**

- 单天行程时，图层 Tab 仍显示 **[总览] [第1天]**（两项完全重复）。
- 0 个有效坐标的日子：dayGroups 会生成空数组，fitBounds 和渲染都安全，但 Tab 仍会出现“第X天”按钮（点击后地图无变化，用户困惑）。
- 行程天数 >7 天时颜色循环，用户无法一眼区分第 8 天和第 1 天。

### 7. **代码维护性与可扩展性问题**

- 三个 export 函数（AMap/Google/Apple）**逻辑高度重复**（单点判断、坐标过滤、URL 拼接），却各自维护，未来加新地图软件（百度、腾讯等）要复制三份代码。
- 所有中文字符串硬编码（警告文案、toast、Tab 文字），国际化成本极高。
- 高德坐标系注释写了“无需转换”，但如果未来接入其他 POI 来源（WGS84），整个 export 模块都要大改。

### 8. **性能与视觉小问题**

- 总览模式下每一天都渲染独立 Polyline + 自定义 HTML Marker，点数多（>50）时 AMap 会卡（自定义 div 比 icon 更耗性能）。
- Tab Bar overflow-x-auto 在手机横屏或天数很多时左右滑动体验差，且没有“更多”省略号提示。
- 路线颜色在总览时用虚线 + 不同色，视觉上已经够区分，却仍强制虚线，显得杂乱。

### 总结建议优先级

**必须修复**（否则功能不合格）：

1. 阈值改成 per-app
2. Polyline 样式加条件判断
3. 标记点编号改成全局序号（总览模式）

**强烈建议优化**：

- 导出改成一步 Sheet（范围 + 地图并列，或默认推荐当前激活天）
- Apple 设备检测改用 navigator.platform + window.ApplePaySession 等更可靠方式
- 抽象一个 MapExporter 基类减少重复代码
